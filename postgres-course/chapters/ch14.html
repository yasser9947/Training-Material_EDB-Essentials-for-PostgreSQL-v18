لماذا COPY بدل INSERT؟Why COPY instead of INSERT?

عند تحميل آلاف أو ملايين الصفوف، INSERT بطيء جداً لأنه يعمل parsing لكل سطر و commit عادة لكل واحد. COPY يتجاوز كل ذلك ويكتب مباشرة.

For thousands/millions of rows, INSERT is slow — parsing each statement, often committing each. COPY bypasses all that and writes directly.

COPY — الأساسيCOPY — The Basics

-- =========== IMPORT ===========

-- Simplest: CSV with header, server-side file
COPY customers(id, name, email)
FROM '/var/data/customers.csv'
WITH (FORMAT csv, HEADER true);

-- Full options
COPY orders FROM '/tmp/orders.csv' WITH (
  FORMAT csv,
  HEADER true,
  DELIMITER ',',
  QUOTE '"',
  ESCAPE '\\',
  NULL 'NULL',           -- treat this string as NULL
  ENCODING 'UTF8',
  FORCE_NOT_NULL (email) -- these columns never NULL
);

-- From STDIN (useful with pipes)
COPY customers FROM STDIN WITH (FORMAT csv, HEADER true);
-- then enter data, end with \.

-- =========== EXPORT ===========

-- Export table to CSV
COPY customers TO '/var/data/export.csv'
WITH (FORMAT csv, HEADER true);

-- Export a query result
COPY (
  SELECT name, email
  FROM customers
  WHERE status = 'active'
) TO '/tmp/active.csv' WITH (FORMAT csv, HEADER true);

-- Export as binary (fastest for round-trip to Postgres)
COPY big_table TO '/tmp/big.bin' WITH (FORMAT binary);
مهم: Important: COPY ... FROM '/path' يقرأ من سيرفر PostgreSQL، يتطلب superuser، والمسار لا بد يكون موجود على السيرفر. COPY ... FROM '/path' reads from the PostgreSQL server, needs superuser, and path must exist on server.

\copy — من جانب العميل\copy — Client-Side

في psql، \copy يقرأ/يكتب ملفات من جهاز العميل، لا من السيرفر. لا يحتاج superuser.

In psql, \copy reads/writes files on the client machine, not server. No superuser needed.

# Inside psql session
\copy customers FROM 'customers.csv' WITH (FORMAT csv, HEADER true)
\copy customers TO 'export.csv' WITH (FORMAT csv, HEADER true)

# From shell — one-liner
psql -d mydb -c "\copy customers FROM 'data.csv' CSV HEADER"

# Stream from URL
curl -s https://example.com/data.csv | \
  psql -d mydb -c "\copy customers FROM STDIN WITH (FORMAT csv, HEADER true)"

# Export and gzip on the fly
psql -d mydb -c "\copy (SELECT * FROM orders) TO STDOUT CSV HEADER" | \
  gzip > orders.csv.gz

# Stream from one DB to another
psql -h source -d mydb -c "\copy customers TO STDOUT" | \
  psql -h target -d mydb -c "\copy customers FROM STDIN"

COPY FREEZE — الأسرع!COPY FREEZE — The Fastest!

COPY FREEZE يدخل الصفوف في حالة frozen مباشرة — يتجنب أول VACUUM FREEZE. مناسب لتحميل البيانات الأولية.

COPY FREEZE inserts rows as frozen immediately — avoids the first VACUUM FREEZE. Great for initial data load.

-- Requirement: table created/truncated in SAME transaction
BEGIN;
  CREATE TABLE huge_import (...);
  COPY huge_import FROM '/data/huge.csv' WITH (FORMAT csv, FREEZE);
COMMIT;

-- Or
BEGIN;
  TRUNCATE staging;
  COPY staging FROM '/data/daily.csv' WITH (FORMAT csv, FREEZE);
COMMIT;

UNLOGGED — للتسريع الأقصىUNLOGGED — For Maximum Speed

الجداول UNLOGGED لا تُكتب إلى WAL — تحميلها أسرع بـ 2-3× لكن تُفقد عند crash.

UNLOGGED tables aren't written to WAL — 2-3× faster loading but lost on crash.

-- Perfect pattern for mega-load
BEGIN;
  -- 1. Create UNLOGGED table (no WAL = faster)
  CREATE UNLOGGED TABLE bulk_stage (LIKE real_table);

  -- 2. Fast load
  COPY bulk_stage FROM '/data/big.csv' WITH (FORMAT csv, FREEZE);

  -- 3. Create indexes AFTER load (much faster this way)
  CREATE INDEX ON bulk_stage (id);
  CREATE INDEX ON bulk_stage (created_at);

  -- 4. Make it durable (converts to logged)
  ALTER TABLE bulk_stage SET LOGGED;

  -- 5. Rename into place
  ALTER TABLE real_table RENAME TO real_table_old;
  ALTER TABLE bulk_stage RENAME TO real_table;
COMMIT;

DROP TABLE real_table_old;
تحذير: Warning: UNLOGGED tables تُمحى عند أي crash للسيرفر! استخدمها فقط للبيانات المؤقتة أو كخطوة وسيطة. UNLOGGED tables are wiped on any server crash! Use only for temp data or intermediate staging.
