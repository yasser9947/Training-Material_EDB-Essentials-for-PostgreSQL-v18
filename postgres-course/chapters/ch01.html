القسم ١Section 1

ما هو PostgreSQL؟What is PostgreSQL?

PostgreSQL نظام إدارة قواعد بيانات علائقية-كائنية (ORDBMS) مفتوح المصدر، يعتبر الأكثر تقدماً في العالم من ناحية المميزات. مطوّر منذ أكثر من ٣٠ سنة ويدعم تقريباً كل ما يخطر ببالك: العلائقية الكلاسيكية، JSON/NoSQL، بيانات جغرافية (PostGIS)، Time-series، البحث النصي الكامل، والآن Vector data للـ AI.

PostgreSQL is the world's most advanced open-source object-relational database management system (ORDBMS). Developed for over 30 years, it supports virtually everything: classical relational, JSON/NoSQL, geospatial (PostGIS), time-series, full-text search, and now vector data for AI.

ليش نقول ORDBMS وليس فقط RDBMS؟Why ORDBMS, not just RDBMS?

PostgreSQL يجمع بين العلائقية (الجداول، الأعمدة، المفاتيح) ومفاهيم الكائنية مثل: الوراثة في الجداول، أنواع بيانات مخصصة، دوال مكتوبة بلغات متعددة، وعمليات (operators) قابلة للتحميل الزائد. هذا الدمج هو ما يعطيه المرونة الاستثنائية.

PostgreSQL combines relational features (tables, columns, keys) with object-oriented concepts: table inheritance, custom data types, functions in multiple languages, and overloadable operators. This hybrid design is what gives it exceptional flexibility.

القسم ٢Section 2

فهم ACID — أساس الموثوقيةUnderstanding ACID — The Reliability Foundation

كل transaction في PostgreSQL يضمن هذه الخصائص الأربعة

Every PostgreSQL transaction guarantees these four properties

A

Atomicity — الذريةAtomicity

العملية كاملها تنفذ أو ولا شيء. إذا تحويل بنكي من حساب لحساب فشل في المنتصف، لا يحدث نصف التحويل — إما الكامل أو لا شيء.

All operations complete or none do. If a bank transfer fails mid-way, no partial transfer occurs — all-or-nothing.

BEGIN → work → COMMIT ✓ or ROLLBACK ✗
C

Consistency — الاتساقConsistency

قاعدة البيانات تنتقل من حالة صحيحة إلى حالة صحيحة أخرى. كل القيود (PRIMARY KEY, FOREIGN KEY, CHECK) تحترم دائماً.

Database moves from valid state to valid state. All constraints (PK, FK, CHECK) are always respected.

CHECK (balance >= 0) — always true
I

Isolation — العزلIsolation

العمليات المتزامنة لا تتداخل — كل transaction يرى قاعدة البيانات كأنه الوحيد. PostgreSQL يدعم ٤ مستويات: Read Uncommitted، Read Committed (الافتراضي)، Repeatable Read، و Serializable.

Concurrent operations don't interfere — each transaction sees the DB as if alone. PostgreSQL supports 4 levels: Read Uncommitted, Read Committed (default), Repeatable Read, Serializable.

D

Durability — الديمومةDurability

بعد COMMIT، البيانات تُحفظ على القرص ولن تُفقد حتى لو انقطعت الكهرباء أو تعطل السيرفر. PostgreSQL يحقق هذا عبر WAL (Write-Ahead Logging).

After COMMIT, data is persisted and won't be lost even on power failure or server crash. PostgreSQL achieves this via WAL (Write-Ahead Logging).

الخط الزمني التاريخيHistorical Timeline

1
1973 – 1985

مشروع IngresIngres Project

بدأ في جامعة كاليفورنيا في بيركلي من قبل Michael Stonebraker. كان أول قاعدة بيانات علائقية تجارية. الاسم اختصار "INteractive GRaphics and REtrieval System".

Started at UC Berkeley by Michael Stonebraker. It was the first commercial relational database. Name stands for "INteractive GRaphics and REtrieval System".

2
1986 – 1993

University PostgresUniversity Postgres

"Post-Ingres" أضاف مفاهيم الكائنية: أنواع بيانات مخصصة، دوال، قواعد، ووراثة الجداول. استخدم لغة QUEL الخاصة.

"Post-Ingres" added object concepts: custom types, functions, rules, table inheritance. Used proprietary QUEL language.

3
1994 – 1995

Postgres95Postgres95

طالبين Andrew Yu و Jolly Chen استبدلوا QUEL بـ SQL. أعلن للعامة تحت رخصة مفتوحة.

Students Andrew Yu and Jolly Chen replaced QUEL with SQL. Released publicly under open license.

4
1996 – 2005

PostgreSQL تولدPostgreSQL is Born

تم تأسيس PostgreSQL Global Development Group. الإصدار 6.0 أصدر في يناير 1997. إضافات مهمة: Write-Ahead Logging، B-tree Indexes، MVCC، ودعم Windows (8.0).

The PostgreSQL Global Development Group was formed. Version 6.0 released January 1997. Key additions: WAL, B-tree indexes, MVCC, Windows support (8.0).

5
2010 – الآنNow

العصر الذهبيThe Golden Age

Streaming Replication (9.0)، JSON (9.2)، JSONB (9.4)، Parallel Query (9.6)، Logical Replication (10)، Partitioning (10)، Stored Procedures (11)، Just-in-Time compilation (11)، ثم v18 مع دعم AI وvector.

Streaming Replication (9.0), JSON (9.2), JSONB (9.4), Parallel Query (9.6), Logical Replication (10), Partitioning (10), Stored Procedures (11), JIT (11), and now v18 with AI/vector support.

القسم ٤Section 4

المميزات الرئيسيةMajor Features

محمول (Portable)Portable

مكتوب بـ ANSI C، يعمل على Linux, Windows, macOS, FreeBSD, Solaris. أي نظام يدعم C قياسي — PostgreSQL يعمل عليه.

Written in ANSI C, runs on Linux, Windows, macOS, FreeBSD, Solaris. Any OS supporting standard C — PostgreSQL runs on it.

موثوق (Reliable)Reliable

ACID كامل، WAL يحمي من انقطاع الكهرباء، Checksums على الصفحات، Savepoints للتراجع الجزئي داخل transaction.

Full ACID, WAL protects from power loss, page checksums, savepoints for partial rollback inside transaction.

قابل للتوسع (Scalable)Scalable

MVCC يسمح بالقراءة والكتابة المتزامنة بدون قفل، Partitioning للجداول العملاقة، Parallel Query، Async I/O. جداول TB بدون مشاكل.

MVCC allows concurrent read/write without locking, partitioning for huge tables, parallel query, async I/O. TB-sized tables work fine.

آمن (Secure)Secure

Host-Based Access Control، SCRAM-SHA-256، SSL/TLS، Row Level Security، Column encryption عبر pgcrypto.

Host-Based Access Control, SCRAM-SHA-256, SSL/TLS, Row Level Security, column encryption via pgcrypto.

استعادة عالية (Recovery)Recovery & HA

Physical و Logical Streaming Replication، Point-in-Time Recovery، Hot Standby، Sync/Async/Cascaded replication.

Physical and Logical Streaming Replication, PITR, Hot Standby, Sync/Async/Cascaded replication.

متقدم (Advanced)Advanced

Triggers، Stored Procedures بـ PL/pgSQL و PL/Python و PL/Perl، Custom types/operators، Foreign Data Wrappers للاتصال بقواعد أخرى.

Triggers, stored procedures in PL/pgSQL, PL/Python, PL/Perl, custom types/operators, Foreign Data Wrappers to connect to other databases.

ماذا يحدث عندما ترسل استعلام؟

What happens when you send a query?

1. Client App
التطبيق يرسل استعلام عبر libpq / JDBC / ODBC
App sends query via libpq / JDBC / ODBC

Accepts connection, authenticates (pg_hba.conf), forks Backend Process

كل مرحلة تحول الاستعلام لشكل أكثر تفصيلاً — تنتهي بخطة تنفيذ محسّنة

نقطة مهمة جداً: Very important: PostgreSQL يستخدم Process Model — كل اتصال جديد = عملية مستقلة (fork). هذا يعطي استقرار ممتاز (عملية واحدة تتعطل لا تؤثر على الباقي) لكن استهلاك ذاكرة أعلى مقارنة بنموذج Threading. لهذا السبب Connection Pooling (PgBouncer) مهم في تطبيقات كبيرة. PostgreSQL uses a process model — each new connection = separate process (fork). This gives excellent stability (one crash doesn't affect others) but higher memory use vs threading. That's why connection pooling (PgBouncer) is critical at scale.

توصيات ذهبية للمبتدئينGolden Rules for Beginners

استخدم UTF-8 دائماً:Always use UTF-8: عند إنشاء الـ Cluster اجعل الترميز UTF-8 للعربية والـ emoji وأي نص عالمي. Initialize cluster with UTF-8 to support Arabic, emoji, and international text.
استخدم timestamptz:Use timestamptz: بدل timestamp العادي — يحفظ المنطقة الزمنية تلقائياً. Not plain timestamp — stores timezone automatically.
text أفضل من varchar:Prefer text over varchar: نفس الأداء والمرونة أعلى. لا تحدد طول إلا لسبب عمل حقيقي. Same performance, more flexible. Don't limit length without real business reason.
لا تشغل كـ root:Never run as root: PostgreSQL يرفض العمل كـ root لأسباب أمنية. PostgreSQL refuses to run as root for security.
