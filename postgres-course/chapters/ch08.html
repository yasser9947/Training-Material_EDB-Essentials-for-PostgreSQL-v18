الأدوار (Roles) بالتفصيلRoles Explained

في PostgreSQL، User = Role + LOGIN. منذ الإصدار 8.1، لا فرق حقيقي بين "مستخدم" و"مجموعة" — كلها أدوار (roles). الفرق فقط في الخصائص:

In PostgreSQL, User = Role + LOGIN. Since 8.1, no real difference between "user" and "group" — they're all roles, just with different attributes:

User (دور مع LOGIN)User (role WITH LOGIN)

يستطيع الاتصال بقاعدة البيانات.

Can connect to the database.

CREATE USER alice PASSWORD 'pass';

Group (دور بدون LOGIN)Group (role WITHOUT LOGIN)

حاوية للصلاحيات — users آخرون يُعطون عضوية فيه.

Privilege container — users are granted membership.

CREATE ROLE developers NOLOGIN;

إدارة الأدوار — أمثلة عمليةRole Management — Practical Examples

-- Create group role (no login)
CREATE ROLE app_readers;
CREATE ROLE app_writers;
CREATE ROLE app_admins;

-- Create users with login
CREATE USER alice WITH PASSWORD 'alice_pw'
  VALID UNTIL '2026-12-31'
  CONNECTION LIMIT 10;

CREATE USER bob WITH PASSWORD 'bob_pw' IN ROLE app_readers;

-- Grant group memberships
GRANT app_writers TO alice;
GRANT app_admins TO alice WITH ADMIN OPTION;  -- Alice can grant further

-- Grant privileges to GROUP (simpler management)
GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_readers;
GRANT INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_writers;

-- Remove membership
REVOKE app_writers FROM alice;

-- Password management
ALTER USER alice WITH PASSWORD 'new_password';
ALTER USER alice VALID UNTIL 'infinity';       -- no expiry
ALTER USER alice VALID UNTIL '2026-06-30';     -- with expiry

-- Disable/enable login
ALTER USER alice NOLOGIN;   -- locks account
ALTER USER alice LOGIN;     -- unlocks

-- Drop user (handle ownership first!)
REASSIGN OWNED BY alice TO postgres;    -- transfer ownership
DROP OWNED BY alice;                     -- drop what alice owns
DROP USER alice;
تحذير أمني: Security warning: استخدم SUPERUSER بحذر شديد — هذا الدور يتجاوز كل فحوصات الأمان! للتطبيقات استخدم أدوار محدودة. Use SUPERUSER carefully — it bypasses ALL security checks! For apps use limited roles.

Tablespaces — التوزيع الماديTablespaces — Physical Distribution

الـ Tablespace موقع على القرص. يسمح بتوزيع البيانات على أقراص مختلفة — مثلاً جدول سريع على SSD والأرشيف على HDD.

A Tablespace is a disk location. Allows distributing data across disks — e.g., hot tables on SSD, archive on HDD.

-- On OS first: create directory, chown to postgres
-- sudo mkdir /mnt/ssd/pgdata && sudo chown postgres:postgres /mnt/ssd/pgdata

-- Create tablespace
CREATE TABLESPACE fast_ssd
  OWNER postgres
  LOCATION '/mnt/ssd/pgdata';

-- Create table in that tablespace
CREATE TABLE hot_orders (id SERIAL, data jsonb)
  TABLESPACE fast_ssd;

-- Move existing table
ALTER TABLE big_logs SET TABLESPACE archive_hdd;

-- Set session default
SET default_tablespace = 'fast_ssd';

-- Database-level default
CREATE DATABASE analytics TABLESPACE ssd_analytics;

-- List tablespaces
SELECT spcname,
       pg_tablespace_location(oid) AS location,
       pg_size_pretty(pg_tablespace_size(oid)) AS size
FROM pg_tablespace;

-- Drop (must be empty first)
DROP TABLESPACE fast_ssd;

Databases و SchemasDatabases & Schemas

-- Create database with options
CREATE DATABASE sales
  OWNER alice
  ENCODING 'UTF8'
  LC_COLLATE 'en_US.UTF-8'
  LC_CTYPE 'en_US.UTF-8'
  TEMPLATE template0
  CONNECTION LIMIT 50;

-- List databases
\l  -- in psql
SELECT datname FROM pg_database;

-- Drop database (must have no connections!)
DROP DATABASE sales;
DROP DATABASE sales WITH (FORCE);  -- kills connections (PG13+)

-- ===== Schemas =====
-- Create schemas
CREATE SCHEMA sales;
CREATE SCHEMA marketing AUTHORIZATION alice;
CREATE SCHEMA IF NOT EXISTS temp_work;

-- Use fully qualified names
CREATE TABLE sales.orders (id SERIAL PRIMARY KEY, ...);
SELECT * FROM sales.orders;

-- search_path (order of lookup)
SHOW search_path;             -- default: "$user", public
SET search_path TO sales, public;
ALTER DATABASE sales SET search_path TO sales, public;

-- Drop schema
DROP SCHEMA temp_work;               -- only if empty
DROP SCHEMA temp_work CASCADE;       -- drops all contents!
schema "public" الآن ليس مكشوفاً! schema "public" is no longer open! منذ PG 15، schema public لم يعد يُعطي CREATE للـ PUBLIC. امنح صلاحيات صريحة: GRANT CREATE ON SCHEMA public TO appuser; Since PG 15, public no longer grants CREATE to PUBLIC. Grant explicitly: GRANT CREATE ON SCHEMA public TO appuser;

GRANT / REVOKE — نظام الصلاحياتGRANT / REVOKE — Privilege System

PostgreSQL له نظام صلاحيات متعدد المستويات. لكي يقرأ مستخدم من جدول، يحتاج:

PostgreSQL has a layered privilege system. To read a table, a user needs:

  1. CONNECT على قاعدة البيانات
  2. CONNECT on the database
  3. USAGE على الـ schema
  4. USAGE on the schema
  5. SELECT على الجدول
  6. SELECT on the table
-- Database privileges
GRANT CONNECT ON DATABASE sales TO analyst;
REVOKE CONNECT ON DATABASE sales FROM PUBLIC;  -- close to public

-- Schema privileges (USAGE = open the schema)
GRANT USAGE ON SCHEMA sales TO analyst;
GRANT CREATE ON SCHEMA sales TO developer;  -- can create objects

-- Table privileges
GRANT SELECT ON customers TO analyst;
GRANT SELECT, INSERT, UPDATE, DELETE ON orders TO app_writers;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA sales TO app_admins;

-- Column-level (restrict to specific columns)
GRANT SELECT (name, email) ON customers TO marketing;

-- Sequence privileges (for AUTO-INCREMENT)
GRANT USAGE, SELECT ON SEQUENCE orders_id_seq TO app_writers;

-- Function privileges
GRANT EXECUTE ON FUNCTION calculate_tax TO app_users;

-- ===== DEFAULT PRIVILEGES for future objects =====
-- When alice creates a table in sales, analyst auto-gets SELECT
ALTER DEFAULT PRIVILEGES FOR ROLE alice
  IN SCHEMA sales
  GRANT SELECT ON TABLES TO analyst;

-- Revoke
REVOKE INSERT ON orders FROM alice;

-- See who has what (in psql)
\dp customers
\z sales.*

أفضل ممارسات التنظيمOrganization Best Practices

استخدم مجموعات (group roles):Use group roles: أعط الصلاحيات للمجموعات، ثم ضع المستخدمين فيها. Grant to groups, then add users to them.
schema لكل تطبيق:Schema per app: لا تخلط جداول تطبيقات مختلفة في public. Don't mix different apps' tables in public.
least privilege:Least privilege: لا تستخدم superuser للتطبيقات. Never use superuser for apps.
كلمات مرور تنتهي:Password expiration: استخدم VALID UNTIL للضغط على التدوير. Use VALID UNTIL to enforce rotation.
