لماذا نحتاج VACUUM؟Why Do We Need VACUUM?

PostgreSQL يستخدم MVCC (Multi-Version Concurrency Control). عند UPDATE أو DELETE، الصفوف القديمة لا تُحذف فوراً — تبقى كـ "Dead Tuples" حتى يأتي VACUUM.

PostgreSQL uses MVCC (Multi-Version Concurrency Control). On UPDATE/DELETE, old rows aren't immediately removed — they become "Dead Tuples" until VACUUM runs.

أوامر الصيانةMaintenance Commands

-- Standard VACUUM (non-blocking)
VACUUM;

-- VACUUM specific table with verbose output
VACUUM VERBOSE customers;

-- VACUUM + ANALYZE together
VACUUM ANALYZE orders;

-- VACUUM FULL (locks table, reclaims disk space)
VACUUM FULL orders;

-- ANALYZE only (updates stats without cleanup)
ANALYZE;
ANALYZE orders (customer_id, order_date);

-- Check bloat
SELECT schemaname, relname, n_dead_tup, n_live_tup,
       ROUND(100.0 * n_dead_tup / NULLIF(n_live_tup + n_dead_tup, 0), 2) AS dead_pct
FROM pg_stat_user_tables
ORDER BY dead_pct DESC NULLS LAST
LIMIT 10;

-- Rebuild indexes
REINDEX TABLE customers;
REINDEX INDEX idx_orders_customer;
REINDEX DATABASE mydb;

-- CONCURRENTLY (doesn't lock writes)
REINDEX INDEX CONCURRENTLY idx_orders_customer;
تنبيه: Warning: VACUUM FULL يقفل الجدول كاملاً ويحتاج مساحة إضافية. لا تستخدمه في ساعات الذروة! VACUUM FULL locks the entire table and needs extra space. Avoid during peak hours!

AutovacuumAutovacuum

Autovacuum عملية خلفية تشغل VACUUM و ANALYZE تلقائياً بناءً على عدد الصفوف المتغيرة.

Autovacuum is a background process that automatically runs VACUUM/ANALYZE based on row changes.

-- Key autovacuum parameters (postgresql.conf)
-- autovacuum = on
-- autovacuum_max_workers = 3
-- autovacuum_naptime = 1min
-- autovacuum_vacuum_threshold = 50
-- autovacuum_vacuum_scale_factor = 0.2    -- 20% of rows
-- autovacuum_analyze_threshold = 50
-- autovacuum_analyze_scale_factor = 0.1   -- 10% of rows

-- Per-table override (for hot tables)
ALTER TABLE orders SET (
  autovacuum_vacuum_scale_factor = 0.05,   -- vacuum at 5%
  autovacuum_analyze_scale_factor = 0.02    -- analyze at 2%
);

-- Check last autovacuum run
SELECT schemaname, relname,
       last_vacuum, last_autovacuum,
       last_analyze, last_autoanalyze,
       vacuum_count, autovacuum_count
FROM pg_stat_user_tables
ORDER BY last_autovacuum DESC NULLS LAST;

Transaction ID WraparoundTransaction ID Wraparound

الـ Transaction IDs في PostgreSQL هي أرقام 32-bit. بعد ~2 مليار transaction، تبدأ الدورة من جديد — وإذا لم يتم تنظيفها، قاعدة البيانات تتوقف!

PostgreSQL transaction IDs are 32-bit. After ~2 billion transactions, they wrap around — if not cleaned, the database halts!

خطر جدي: Serious danger: إذا لم يعمل VACUUM، ستصل قاعدة البيانات إلى حالة FROZEN وتتوقف عن قبول كتابة جديدة. تأكد دائماً من عمل autovacuum! Without VACUUM, the database enters FROZEN state and refuses new writes. Always ensure autovacuum is running! 
-- Monitor transaction age
SELECT datname,
       age(datfrozenxid) AS xid_age,
       ROUND(100.0 * age(datfrozenxid) / 2000000000, 2) AS pct_to_wraparound
FROM pg_database
ORDER BY xid_age DESC;

-- If wraparound approaching, run VACUUM FREEZE
VACUUM FREEZE;
