pg_stat_statements — الأساسي!pg_stat_statements — Essential!

هذا الـ extension يعطيك أكثر الاستعلامات استهلاكاً للوقت في قاعدة بياناتك — لا يوجد DBA محترف بدونه.

This extension gives you the top time-consuming queries in your DB — no serious DBA works without it.

-- Install
CREATE EXTENSION pg_stat_statements;

-- Add to postgresql.conf:
-- shared_preload_libraries = 'pg_stat_statements'
-- pg_stat_statements.max = 10000
-- pg_stat_statements.track = all
-- (restart required)

-- Top 10 slowest queries (by total time)
SELECT substring(query, 1, 80) AS query,
       calls,
       ROUND(total_exec_time::numeric, 2) AS total_ms,
       ROUND(mean_exec_time::numeric, 2) AS avg_ms,
       rows
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 10;

-- Top queries by average time (find inefficient ones)
SELECT substring(query, 1, 80) AS query,
       calls, ROUND(mean_exec_time::numeric, 2) AS avg_ms
FROM pg_stat_statements
WHERE calls > 50
ORDER BY mean_exec_time DESC
LIMIT 10;

-- Query patterns consuming most I/O
SELECT substring(query, 1, 80) AS query,
       shared_blks_read + shared_blks_hit AS total_blocks,
       ROUND(100.0 * shared_blks_hit / NULLIF(shared_blks_read + shared_blks_hit, 0), 2) AS cache_hit
FROM pg_stat_statements
ORDER BY shared_blks_read DESC
LIMIT 10;

-- Reset statistics
SELECT pg_stat_statements_reset();

إدارة الأقفال (Locks)Lock Management

عند توقف التطبيق مفاجئاً، غالباً السبب blocking lock. هذه استعلامات لتشخيصها:

When the app hangs suddenly, it's often a blocking lock. Use these to diagnose:

-- 1. Find who is blocking whom (single query — PG9.6+)
SELECT blocked.pid         AS blocked_pid,
       blocked.usename     AS blocked_user,
       blocked.state       AS blocked_state,
       blocking.pid        AS blocking_pid,
       blocking.usename    AS blocking_user,
       blocking.state      AS blocking_state,
       NOW() - blocked.query_start AS blocked_duration,
       LEFT(blocked.query, 60)  AS blocked_query,
       LEFT(blocking.query, 60) AS blocking_query
FROM pg_stat_activity AS blocked
JOIN pg_stat_activity AS blocking
     ON blocking.pid = ANY(pg_blocking_pids(blocked.pid))
ORDER BY blocked.query_start;

-- 2. All locks overview
SELECT locktype, relation::regclass AS table,
       mode, transactionid, virtualtransaction,
       pid, granted
FROM pg_locks
WHERE NOT granted
ORDER BY pid;

-- 3. Cancel the blocker (graceful)
SELECT pg_cancel_backend(<blocking_pid>);

-- 4. If won't cancel — terminate
SELECT pg_terminate_backend(<blocking_pid>);

-- 5. Find long-running idle-in-transaction (dangerous!)
SELECT pid, usename, state, NOW() - xact_start AS tx_age, query
FROM pg_stat_activity
WHERE state = 'idle in transaction'
  AND NOW() - xact_start > interval '5 minutes';
خطر خفي: Hidden danger: idle in transaction — عميل فتح transaction ولم يكمل. يمنع VACUUM ويعطل الأداء. استخدم idle_in_transaction_session_timeout لإغلاقها تلقائياً. idle in transaction — client opened a transaction but never finished. Blocks VACUUM and hurts performance. Use idle_in_transaction_session_timeout to auto-kill.

  -e DATA_SOURCE_NAME="postgresql://monitor:pw@db:5432/postgres?sslmode=disable" \
  -p 9187:9187 \
  quay.io/prometheuscommunity/postgres-exporter

# 2. Create monitor user in Postgres
CREATE USER monitor WITH PASSWORD 'pw';
GRANT pg_monitor TO monitor;  -- built-in role with read access
