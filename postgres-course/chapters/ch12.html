RTO و RPO — حدد هدفك أولاًRTO & RPO — Define Goals First

RTORecovery Time Objective

كم من الوقت تتحمل أن تكون قاعدة البيانات معطلة؟

How long can the DB be down?

مثال: أقل من ٥ دقائقExample: < 5 minutes

RPORecovery Point Objective

كم من البيانات تتحمل فقدانها؟

How much data can you lose?

مثال: أقل من ثانيةExample: < 1 second
مثال: بنك — RTO = دقيقة، RPO = ٠ (replication). مدونة شخصية — RTO = ٢٤h، RPO = يوم (dump يومي).
Example: Bank — RTO = minute, RPO = 0 (replication). Personal blog — RTO = 24h, RPO = day (daily dump).

pg_dump — التفاصيل الكاملةpg_dump — Full Details

# 4 output formats:

# 1. Plain SQL (human-readable, simple)
pg_dump -U postgres -d mydb -f mydb.sql

# 2. Custom (compressed, selective restore supported) — recommended
pg_dump -U postgres -d mydb -F c -Z 9 -f mydb.dump

# 3. Directory (parallel dump/restore)
pg_dump -U postgres -d mydb -F d -j 4 -f mydb_dir/

# 4. Tar archive
pg_dump -U postgres -d mydb -F t -f mydb.tar

# --- Selective options ---
# Schema only (no data) — for versioning
pg_dump -d mydb --schema-only -f schema.sql

# Data only — for migrations
pg_dump -d mydb --data-only -f data.sql

# Specific tables
pg_dump -d mydb -t customers -t orders -f tables.sql

# Specific schema
pg_dump -d mydb -n sales -f sales.sql

# Exclude tables (e.g., logs)
pg_dump -d mydb -T logs -T audit_* -f mydb.sql

# All databases + global (roles, tablespaces)
pg_dumpall -U postgres -f all.sql
pg_dumpall --globals-only -f globals.sql   # just globals

# --- Restore ---
psql -U postgres -d mydb -f mydb.sql                # plain SQL
pg_restore -U postgres -d mydb mydb.dump           # custom format
pg_restore -U postgres -d mydb -j 4 mydb_dir/      # parallel

# Restore specific table from custom-format dump
pg_restore -U postgres -d mydb -t customers mydb.dump

# See contents of custom dump
pg_restore --list mydb.dump

pg_basebackup للنسخ الماديpg_basebackup for Physical Backup

يأخذ snapshot كامل من الكلاستر وهو شغّال — مفيد جداً للقواعد الكبيرة و PITR.

Takes a full cluster snapshot while live — crucial for large DBs and PITR.

# Prereq: create replication user
CREATE USER backup REPLICATION LOGIN PASSWORD 'bk_pw';
# Edit pg_hba.conf — allow replication for this user

# Base backup
pg_basebackup \
  -h primary.host \
  -U backup \
  -D /backup/base_$(date +%Y%m%d) \
  -F t \                      # tar format
  -z \                        # gzip compress
  -P \                        # show progress
  -X stream \                 # include WAL via streaming
  -c fast \                   # fast checkpoint
  -R \                        # write standby.signal (ready for replica)
  --wal-method=stream         # default in PG12+

# Result (tar format):
ls /backup/base_20260422/
# base.tar.gz  pg_wal.tar.gz

Point-in-Time Recovery (PITR)Point-in-Time Recovery (PITR)

PITR يسمح باستعادة القاعدة إلى أي لحظة زمنية في الماضي. مفيد بعد حذف خاطئ.

PITR lets you restore to any point in time in the past. Invaluable after an accidental delete.

المعادلة السحرية:The magic formula:

PITR = pg_basebackup + continuous WAL archive
# ========== STEP 1: Enable WAL archiving ==========
# postgresql.conf:
wal_level = replica
archive_mode = on
archive_command = 'test ! -f /archive/%f && cp %p /archive/%f'
# restart needed

# ========== STEP 2: Take periodic base backups ==========
# Weekly (cron)
pg_basebackup -D /backup/weekly_$(date +%Y%m%d) -Ft -z -P -U backup

# ========== STEP 3: Disaster strikes! ==========
# Bad query at 14:30 deleted 10,000 orders
# We want to restore to 14:29

# ========== STEP 4: Recovery ==========
# 1. Stop current server
pg_ctl stop -m fast

# 2. Move old data dir (don't delete — keep for forensics)
mv /var/lib/pgsql/18/data /var/lib/pgsql/18/data.broken

# 3. Restore base backup
mkdir /var/lib/pgsql/18/data
tar -xzf /backup/weekly_20260420/base.tar.gz -C /var/lib/pgsql/18/data/

# 4. Configure recovery (PG12+: in postgresql.auto.conf + signal file)
touch /var/lib/pgsql/18/data/recovery.signal
cat >> /var/lib/pgsql/18/data/postgresql.auto.conf << EOF
restore_command = 'cp /archive/%f %p'
recovery_target_time = '2026-04-22 14:29:00+00'
recovery_target_action = 'promote'   # or 'pause' to inspect first
EOF

# 5. Start — replays WAL until target
pg_ctl start

# 6. Verify, then use SELECT pg_wal_replay_resume(); if paused
أهداف recovery الممكنة: Recovery targets:
  • recovery_target_time = '...'
  • recovery_target_xid = '12345'
  • recovery_target_lsn = '1/300000'
  • recovery_target_name = 'before_drop'
  • recovery_target = 'immediate'
recovery_target_action: recovery_target_action:
  • pause — توقف للفحص — pause to inspect
  • promote — أصبح primary — become primary
  • shutdown — أوقف — stop
