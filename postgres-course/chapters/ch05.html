ما هو الكلاستر؟What is a Cluster?

الكلاستر (Database Cluster) في PostgreSQL مصطلح قد يختلف عن ما تعرفه. هنا لا يعني مجموعة سيرفرات متصلة — بل يعني مجموعة قواعد بيانات يديرها سيرفر PostgreSQL واحد. الكلاستر = مجلد بيانات + منفذ + عملية سيرفر واحدة.

In PostgreSQL, "cluster" may differ from what you know. It does NOT mean a group of connected servers — it means a set of databases managed by a single PostgreSQL server. Cluster = data directory + port + one server process.

initdb — إنشاء كلاستر جديدinitdb — Creating a New Cluster

initdb يُشغّل مرة واحدة فقط لكل كلاستر — ينشئ بنية المجلد، ملفات النظام، والقواعد الافتراضية.

initdb runs only ONCE per cluster — creates directory structure, system files, and default databases.

# Basic — only required: -D (data dir)
initdb -D /var/lib/pgsql/18/data

# Recommended options:
initdb -D /var/lib/pgsql/18/edbdata \
       --encoding=UTF8 \                   # UTF-8 for Arabic/emoji
       --locale=en_US.UTF-8 \              # for text ordering
       -U postgres \                        # DB superuser name
       --pwprompt \                         # prompt for password
       --auth-host=scram-sha-256 \          # secure auth for network
       --auth-local=peer \                  # OS user for local
       --data-checksums                     # corruption detection

# After initdb:
ls /var/lib/pgsql/18/edbdata
# base  global  pg_hba.conf  pg_wal  postgresql.conf ...

# Start the server
pg_ctl -D /var/lib/pgsql/18/edbdata -l logfile start
مهم جداً: Critical: --data-checksums يجب إضافتها عند initdb — لا يمكن تفعيلها لاحقاً (لكن في PostgreSQL 18 هناك أدوات لتفعيلها بدون re-init، لكن العملية معقدة). فعّلها من البداية! --data-checksums must be set at initdb time — tools exist to enable later in PG18 but the process is complex. Enable from day one!

pg_ctl — إدارة السيرفرpg_ctl — Server Management

export PGDATA=/var/lib/pgsql/18/data

# Start
pg_ctl start -l /var/log/postgresql.log

# Status (running or not)
pg_ctl status

# Reload config (NO restart — for postgresql.conf changes)
pg_ctl reload
# Equivalent SQL: SELECT pg_reload_conf();

# Restart (for params requiring restart)
pg_ctl restart

# Stop — 3 modes
pg_ctl stop -m smart         # wait for clients to disconnect
pg_ctl stop -m fast          # default: rollback + disconnect
pg_ctl stop -m immediate     # abrupt — recovery needed on next start

# Promote (convert standby to primary)
pg_ctl promote

# Check version
pg_ctl --version

smart

ينتظر كل العملاء ينتهون — مثالي لكن قد يأخذ وقتاً طويلاً

Waits for all clients — ideal but may take long

fast (default)

يقطع الاتصالات، يعمل rollback للمعلّقات، ثم يوقف. الأكثر استخداماً

Disconnects, rollback pending, stops. Most commonly used

immediate

يتوقف فوراً — مثل kill. يحتاج WAL recovery عند التشغيل. للطوارئ فقط

Stops immediately — like kill. Needs WAL recovery on start. Emergency only

systemctl vs pg_ctlsystemctl vs pg_ctl

في بيئة الإنتاج على Linux، استخدم systemctl (يعمل كـ service مع init system). pg_ctl للتطوير أو لـ scripts مخصصة.

In production Linux, use systemctl (runs as service with init system). pg_ctl is for dev or custom scripts.

sudo systemctl start postgresql-18     # start
sudo systemctl stop postgresql-18      # stop (fast mode)
sudo systemctl restart postgresql-18   # restart
sudo systemctl reload postgresql-18    # SIGHUP (reload conf only)
sudo systemctl status postgresql-18    # health check
sudo systemctl enable postgresql-18    # auto-start on boot
sudo journalctl -u postgresql-18 -f    # live log tailing

عدة كلاسترات على سيرفر واحدMultiple Clusters Per Server

يمكن تشغيل عدة كلاسترات على نفس السيرفر — كل واحد بمجلد ومنفذ مختلفين. مفيد للفصل بين بيئات التطوير والاختبار.

You can run multiple clusters on one server — each with its own directory and port. Useful for separating dev/test environments.

# Create 2nd cluster on port 5433
sudo -u postgres /usr/pgsql-18/bin/initdb -D /var/lib/pgsql/18/test_data

# Edit postgresql.conf in that directory:
# port = 5433

# Start it manually (not via systemd)
sudo -u postgres /usr/pgsql-18/bin/pg_ctl \
  -D /var/lib/pgsql/18/test_data \
  -l /tmp/test.log start

# Connect to each
psql -p 5432 -U postgres   # main cluster
psql -p 5433 -U postgres   # test cluster

# On Ubuntu/Debian it's much easier:
pg_createcluster 18 testing --port=5433 --start
pg_lsclusters
