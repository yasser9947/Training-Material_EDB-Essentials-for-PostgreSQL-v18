pg_hba.conf — القلب النابض للأمانpg_hba.conf — Security's Beating Heart

HBA = Host-Based Authentication. يُقرأ من الأعلى للأسفل، وأول سطر مطابق يحكم. ترتيب القواعد مهم جداً!

HBA = Host-Based Authentication. Read top-to-bottom, first match wins. Rule order matters!

# TYPE     DATABASE     USER          ADDRESS              METHOD    [options]
#
# local    = Unix socket (same machine)
# host     = TCP/IP (SSL optional)
# hostssl  = TCP/IP with SSL required
# hostnossl= TCP/IP without SSL

# --- Local connections ---
local     all          postgres                             peer
local     all          all                                  scram-sha-256

# --- Local loopback ---
host      all          all           127.0.0.1/32         scram-sha-256
host      all          all           ::1/128              scram-sha-256

# --- Office subnet: only app team ---
host      appdb        app_user      10.0.1.0/24          scram-sha-256

# --- Replication ---
host      replication  replicator    192.168.1.0/24       scram-sha-256

# --- External: require SSL + cert ---
hostssl   all          all           0.0.0.0/0            cert clientcert=verify-full

# --- Default deny (explicit) ---
host      all          all           0.0.0.0/0            reject
تذكر: Remember: بعد أي تعديل على pg_hba.conf نفذ SELECT pg_reload_conf(); أو pg_ctl reload. لا تحتاج restart. After any pg_hba.conf change run SELECT pg_reload_conf(); or pg_ctl reload. No restart needed.

SSL/TLS — تشفير الاتصالSSL/TLS — Connection Encryption

لحماية كلمات المرور والبيانات أثناء النقل عبر الشبكة:

To protect passwords and data in transit:

# 1. Generate self-signed cert (or use Let's Encrypt)
openssl req -new -x509 -days 365 -nodes -text \
  -out /var/lib/pgsql/18/data/server.crt \
  -keyout /var/lib/pgsql/18/data/server.key \
  -subj "/CN=db.example.com"

chmod 600 /var/lib/pgsql/18/data/server.key
chown postgres:postgres /var/lib/pgsql/18/data/server.*

# 2. In postgresql.conf:
ssl = on
ssl_cert_file = 'server.crt'
ssl_key_file = 'server.key'
ssl_min_protocol_version = 'TLSv1.2'
ssl_ciphers = 'HIGH:!aNULL:!MD5'

# 3. In pg_hba.conf — enforce SSL
hostssl all all 0.0.0.0/0 scram-sha-256

# 4. Restart server
pg_ctl restart

# 5. Client verification (in app/connection string)
psql "postgresql://user@host/db?sslmode=verify-full&sslrootcert=ca.crt"
disable لا SSL no SSL
prefer اختياري optional
require مطلوب required
verify-ca + تحقق CA + CA check
verify-full أقوى — يتحقق من hostname أيضاً strongest — also verifies hostname

Row Level Security (RLS)Row Level Security (RLS)

الـ RLS يقيّد الصفوف التي يراها كل مستخدم — ممتاز للتطبيقات multi-tenant حيث كل عميل يرى بياناته فقط.

RLS restricts which rows each user sees — excellent for multi-tenant apps where each customer sees only their own data.

-- Example: invoices table with tenant_id
CREATE TABLE invoices (
  id          SERIAL PRIMARY KEY,
  tenant_id   TEXT NOT NULL,
  amount      NUMERIC,
  details     TEXT
);

-- 1. Enable RLS on the table
ALTER TABLE invoices ENABLE ROW LEVEL SECURITY;

-- 2. Create policies

-- Policy A: tenants see only their own rows
CREATE POLICY tenant_isolation ON invoices
  FOR ALL                                    -- SELECT, INSERT, UPDATE, DELETE
  USING (tenant_id = current_setting('app.tenant'))
  WITH CHECK (tenant_id = current_setting('app.tenant'));

-- Policy B: admins see everything
CREATE POLICY admin_all ON invoices
  FOR ALL
  TO superadmin_role
  USING (true);

-- 3. Set the session variable from app code (per request)
SET app.tenant = 'acme_inc';

-- Now SELECT automatically filters:
SELECT * FROM invoices;   -- only acme_inc rows visible

-- FORCE RLS on table owner too (owner bypasses by default)
ALTER TABLE invoices FORCE ROW LEVEL SECURITY;

-- Disable RLS (careful!)
ALTER TABLE invoices DISABLE ROW LEVEL SECURITY;

-- List policies
\d+ invoices
SELECT * FROM pg_policies WHERE tablename = 'invoices';
تنبيه: Note: بدون سياسات، ENABLE RLS = لا أحد يرى شيء (default deny). ومالك الجدول يتجاوز RLS افتراضياً ما لم تستخدم FORCE. Without policies, ENABLE RLS = no one sees anything (default deny). Table owner bypasses RLS by default unless you use FORCE.

pgcrypto للحقول الحساسة

pgcrypto for sensitive fields

-- Install pgcrypto
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- Hash password (for storing, not encryption)
SELECT crypt('mypassword', gen_salt('bf'));   -- bcrypt
-- Verify
SELECT crypt('mypassword', stored_hash) = stored_hash;

-- Symmetric encryption (AES)
INSERT INTO secrets (id, data)
VALUES (1, pgp_sym_encrypt('credit card: 4111...', 'secret_key'));

-- Decrypt
SELECT pgp_sym_decrypt(data::bytea, 'secret_key') FROM secrets WHERE id = 1;

-- Generate random UUIDs (cryptographically secure)
SELECT gen_random_uuid();

التدقيق بـ pgauditAuditing with pgaudit

pgaudit extension يسجل العمليات الحساسة بتفاصيل كاملة — مطلوب لـ HIPAA، PCI-DSS، GDPR.

pgaudit extension logs sensitive operations in detail — required for HIPAA, PCI-DSS, GDPR.

# Install pgaudit extension
sudo dnf install pgaudit_18

# In postgresql.conf:
shared_preload_libraries = 'pgaudit'
pgaudit.log = 'write, ddl, role'
# Classes: read, write, function, role, ddl, misc, all

# Per-database or per-role auditing
ALTER DATABASE sales SET pgaudit.log = 'all';
ALTER ROLE finance SET pgaudit.log = 'read, write';

# Restart to activate
sudo systemctl restart postgresql-18
